# Complete Java Interview Questions and Answers (1–195)

I'll provide answers in simple, easy-to-understand English, written in a way you can directly speak during a technical interview.

For every question, I'll focus on:

- Simple definition.
- How it works.
- Small examples wherever useful.
- Important differences that interviewers commonly ask.

The answers are suitable for a fresher or a 0–2 years Java Developer interview. Don't try to memorize every word. Understand the concept and explain it naturally.

# A. Java Fundamentals (1–40)

### 1. What is Java?

Java is a high-level, object-oriented, platform-independent programming language.

It is mainly used to develop web applications, mobile applications, enterprise applications and backend systems.

Interview answer: Java is a platform-independent programming language that follows the principle of Write Once, Run Anywhere.

### 2. What are the main features of Java?

The main features are:

1. Platform-independent: Runs on different operating systems using JVM.
2. Object-oriented: Supports classes and objects.
3. Simple: Easy to learn compared to languages like C++.
4. Secure: Provides bytecode verification and runtime security features.
5. Robust: Supports exception handling and garbage collection.
6. Multithreaded: Can execute multiple tasks simultaneously.
7. Portable: Java programs can run on different platforms.
8. High performance: Uses JIT compilation to improve execution speed.

### 3. Why is Java platform-independent?

Java is platform-independent because its source code is compiled into bytecode instead of directly into machine code.

This bytecode can run on any operating system that has a compatible JVM.

For example, the same Java bytecode can run on Windows, Linux and macOS.

### 4. Explain WORA (Write Once, Run Anywhere).

WORA means Write Once, Run Anywhere.

We write Java code once and compile it into bytecode. That bytecode can run on different operating systems using their respective JVMs.

For example, a Java program compiled on Windows can also run on Linux without recompiling, provided a compatible Java runtime is available.

### 5. What is the difference between JDK, JRE and JVM?

- JDK (Java Development Kit): Used to develop and compile Java applications. It contains development tools and the runtime components.
- JRE (Java Runtime Environment): Provides the environment required to run Java applications.
- JVM (Java Virtual Machine): Executes Java bytecode.

Remember:

- JDK = Development + Runtime.
- JRE = Runtime environment.
- JVM = Executes bytecode.

### 6. Explain the architecture of JVM.

JVM mainly contains the following components:

1. Class Loader: Loads compiled class files.
2. Runtime Data Areas: Stores data required during program execution.
3. Execution Engine: Executes bytecode.
4. Garbage Collector: Removes unused objects.
5. JNI: Allows Java code to interact with native applications and libraries.

The runtime memory areas include:

- Heap
- Java Stack
- Method Area
- PC Register
- Native Method Stack

### 7. What is bytecode?

Bytecode is the intermediate code generated by the Java compiler.

When we compile a Java file using `javac`, it generates a `.class` file containing bytecode.

The JVM executes this bytecode.

Example:

```
javac Hello.java
```

This generates:

```
Hello.class
```

### 8. How does a Java program execute internally?

The execution process is:

1. Write Java code in a `.java` file.
2. The Java compiler (`javac`) compiles it.
3. Bytecode is generated in a `.class` file.
4. Class Loader loads the class.
5. Bytecode Verifier checks bytecode safety.
6. JVM Execution Engine executes the bytecode.
7. JIT compiler converts frequently executed bytecode into native machine code for better performance.

### 9. Why is Java not completely object-oriented?

Java is not considered purely object-oriented because it supports primitive data types.

For example:

```
int a = 10;
double b = 20.5;
char c = 'A';
```

These are not objects.

However, Java provides wrapper classes such as `Integer`, `Double` and `Character` to represent primitive values as objects.

### 10. What are primitive and non-primitive data types?

Primitive data types store simple values directly.

Java has eight primitive types:

- byte
- short
- int
- long
- float
- double
- char
- boolean

Non-primitive data types refer to objects or reference types.

Examples:

- String
- Arrays
- Classes
- Interfaces
- Objects

Example:

```
int a = 10;           // Primitive
String name = "Abi";  // Non-primitive
```

### 11. What is type casting?

Type casting means converting one data type into another.

For example, converting an integer into a double or a double into an integer.

Java supports two types:

1. Implicit casting.
2. Explicit casting.

### 12. What is the difference between implicit and explicit casting?

Implicit casting: Automatically converts a smaller compatible type into a larger type.

```
int a = 10;
double b = a;
```

Explicit casting: Manually converts a larger type into a smaller type.

```
double a = 10.5;
int b = (int) a;
```

Output: `10`

Explicit casting can cause data loss.

### 13. What are wrapper classes?

Wrapper classes convert primitive data types into objects.

Examples:

| Primitive | Wrapper   |
| --------- | --------- |
| int       | Integer   |
| char      | Character |
| double    | Double    |
| float     | Float     |
| boolean   | Boolean   |
| long      | Long      |
| short     | Short     |
| byte      | Byte      |

Example:

```
int a = 10;
Integer b = Integer.valueOf(a);
```

Wrapper classes are useful when working with collections because collections store objects rather than primitive values.

### 14. What is autoboxing and unboxing?

Autoboxing: Automatically converting a primitive into its corresponding wrapper object.

```
int a = 10;
Integer b = a;
```

Unboxing: Automatically converting a wrapper object into a primitive.

```
Integer a = 20;
int b = a;
```

### 15. What is the difference between stack and heap memory?

| Stack                                              | Heap                                        |
| -------------------------------------------------- | ------------------------------------------- |
| Stores method call frames and local variables      | Stores objects and arrays                   |
| Each thread has its own stack                      | Shared across threads                       |
| Memory is managed through method calls and returns | Objects are reclaimed by garbage collection |
| Generally faster to access                         | Generally slower than stack access          |

Example:

```
class Student {
    public static void main(String[] args) {
        int age = 20;
        Student s = new Student();
    }
}
```

Here, the local variable `age` and reference variable `s` are in the method's stack frame. The actual Student object is in the heap.

### 16. What is garbage collection?

Garbage collection is the automatic memory management process in Java.

It identifies objects that are no longer reachable and reclaims their memory.

This reduces the need for programmers to manually free memory.

### 17. How does garbage collection work?

Garbage collection mainly works by identifying reachable and unreachable objects.

1. JVM identifies objects reachable from GC roots.
2. Objects that cannot be reached are considered eligible for garbage collection.
3. The garbage collector reclaims their memory.

GC roots include active thread stacks, static references and certain JVM internal references.

We can request garbage collection using:

```
System.gc();
```

However, it is only a request. JVM does not guarantee immediate garbage collection.

### 18. What is a Class Loader?

A Class Loader is a JVM component responsible for loading Java class files into memory when required.

The main built-in class loaders are:

1. Bootstrap Class Loader.
2. Platform Class Loader.
3. Application Class Loader.

For example, when we create an object of a class, JVM ensures that the class is loaded before using it.

### 19. What is the JIT compiler?

JIT stands for Just-In-Time compiler.

It is part of the JVM execution engine.

It converts frequently executed bytecode into native machine code to improve application performance.

### 20. What is the difference between compile-time and runtime?

Compile-time: The stage when the Java compiler checks and compiles the source code.

Example: Syntax errors and incompatible types.

Runtime: The stage when the program is actually executing.

Example: NullPointerException and ArithmeticException.

### 21. What are local, instance and static variables?

Local variable: Declared inside a method, constructor or block. It must be initialized before use.

Instance variable: Declared inside a class but outside methods. Each object has its own copy.

Static variable: Declared using the `static` keyword. One shared copy belongs to the class.

Example:

```
class Student {
    int age = 20;             // Instance variable
    static String college = "ACCET"; // Static variable

    void display() {
        int marks = 90;       // Local variable
    }
}
```

### 22. What is a static block?

A static block is a block of code declared using the `static` keyword.

It executes when the class is initialized, before the first active use that triggers initialization.

It is mainly used to initialize static variables.

```
class Demo {
    static {
        System.out.println("Static block");
    }
}
```

### 23. Can we overload the main() method?

Yes. We can overload the main method by changing its parameters.

```
public class Demo {
    public static void main(String[] args) {
        System.out.println("Main method");
        main(10);
    }

    public static void main(int a) {
        System.out.println(a);
    }
}
```

JVM starts execution using the standard entry-point method, not the overloaded method.

### 24. Why is the main() method static?

The main method is static because JVM can call it without creating an object of the class.

If it were non-static, JVM would need to create an object first.

### 25. Can we execute a Java program without the main() method?

For a normal standalone Java application, the traditional entry point is:

```
public static void main(String[] args)
```

Modern Java also supports launching simple source files and instance main methods in certain Java versions through compact source files and flexible constructor bodies, depending on the JDK version.

But for a traditional interview question, the expected answer is that a standalone Java application needs a valid entry point.

### 26. What is a constructor?

A constructor is a special member of a class used to initialize objects.

Important points:

- Its name must match the class name.
- It does not have a return type.
- It is called when an object is created.

```
class Student {
    Student() {
        System.out.println("Constructor called");
    }
}
```

### 27. What are the types of constructors?

Commonly, we discuss:

1. Default constructor: Automatically provided by the compiler if no constructor is declared.
2. No-argument constructor: A constructor written without parameters.
3. Parameterized constructor: Accepts parameters to initialize an object.

### 28. What is constructor overloading?

Constructor overloading means having multiple constructors in the same class with different parameter lists.

```
class Student {
    Student() {
        System.out.println("Default");
    }

    Student(String name) {
        System.out.println(name);
    }
}
```

### 29. Can a constructor be inherited?

No. Constructors are not inherited by child classes.

However, a child constructor can call a parent constructor using `super()`.

### 30. Can a constructor be overridden?

No. Constructor overriding is not possible because constructors are not inherited.

However, constructors can be overloaded.

### 31. What is the `this` keyword?

The `this` keyword refers to the current object.

It is commonly used to differentiate instance variables from local variables.

```
class Student {
    int age;

    Student(int age) {
        this.age = age;
    }
}
```

Here, `this.age` refers to the instance variable.

### 32. What is the `super` keyword?

The `super` keyword refers to the immediate parent class.

It is used to:

1. Access parent class variables.
2. Call parent class methods.
3. Call parent class constructors.

```
class Parent {
    void display() {
        System.out.println("Parent");
    }
}

class Child extends Parent {
    void show() {
        super.display();
    }
}
```

### 33. What is the `static` keyword?

The static keyword belongs to the class rather than individual objects.

It can be used with:

- Variables
- Methods
- Blocks
- Nested classes

A static variable is shared among all objects of the class.

### 34. What is the `final` keyword?

The final keyword is used to restrict modification.

- Final variable: Cannot be reassigned after initialization.
- Final method: Cannot be overridden.
- Final class: Cannot be inherited.

Example:

```
final int age = 20;
```

### 35. What is the difference between final, finally and finalize()?

| final                                    | finally                          | finalize()                                  |
| ---------------------------------------- | -------------------------------- | ------------------------------------------- |
| Keyword                                  | Block                            | Method                                      |
| Restricts modification or inheritance    | Used in exception handling       | Historically associated with object cleanup |
| Used with variables, methods and classes | Usually executes after try/catch | Deprecated and unreliable                   |

`finalize()` is deprecated for removal and should not be used for resource management.

### 36. What is the difference between == and equals()?

`==` compares primitive values or checks whether two reference variables refer to the same object.

`equals()` compares object contents when the class implements an appropriate equality definition.

Example:

```
String a = new String("Java");
String b = new String("Java");

System.out.println(a == b);      // false
System.out.println(a.equals(b)); // true
```

### 37. What is the hashCode() method?

`hashCode()` is a method that returns an integer hash value for an object.

It is mainly used by hash-based collections like HashMap and HashSet to locate objects efficiently.

### 38. What is the contract between equals() and hashCode()?

There are two important rules:

1. If two objects are equal according to `equals()`, they must have the same hash code.
2. If two objects have the same hash code, they do not necessarily have to be equal.

This is important when using HashMap and HashSet.

### 39. What is an immutable class?

An immutable class is a class whose object state cannot be changed after creation.

Example: String.

Once we create a String object, we cannot modify its original value.

### 40. How do you create an immutable class in Java?

Steps:

1. Declare the class as `final`.
2. Make instance variables `private final`.
3. Initialize variables through the constructor.
4. Do not provide setter methods.
5. Return defensive copies of mutable objects.

Example:

```
final class Student {
    private final String name;
    private final int age;

    Student(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String getName() {
        return name;
    }

    public int getAge() {
        return age;
    }
}
```

This example is immutable because String and int are immutable/value types, and no setter methods are provided.

# B. OOP Concepts (41–70)

### 41. What is Object-Oriented Programming?

OOP is a programming approach based on classes and objects.

It helps organize code, improve reusability, maintainability and security.

### 42. What are the four pillars of OOP?

The four pillars are:

1. Encapsulation.
2. Inheritance.
3. Polymorphism.
4. Abstraction.

### 43. What is encapsulation?

Encapsulation means wrapping data and methods together inside a class and controlling access to that data.

For example, making variables private and providing public getter and setter methods.

### 44. How do you implement encapsulation in Java?

We implement encapsulation by:

1. Declaring variables as private.
2. Providing public getter and setter methods when appropriate.

```
class Employee {
    private int salary;

    public void setSalary(int salary) {
        this.salary = salary;
    }

    public int getSalary() {
        return salary;
    }
}
```

### 45. What is inheritance?

Inheritance is an OOP concept where one class acquires the properties and methods of another class.

It improves code reusability.

Example:

```
class Animal {
    void eat() {
        System.out.println("Eating");
    }
}

class Dog extends Animal {
}
```

Here, Dog inherits the `eat()` method from Animal.

### 46. What are the different types of inheritance?

The types are:

1. Single inheritance.
2. Multilevel inheritance.
3. Hierarchical inheritance.
4. Multiple inheritance.
5. Hybrid inheritance.

Java supports single, multilevel and hierarchical inheritance through classes.

Multiple and hybrid inheritance can be achieved through interfaces, with appropriate conflict handling.

### 47. Why does Java not support multiple inheritance through classes?

Java does not support multiple inheritance through classes to avoid ambiguity.

For example, if two parent classes contain the same method, the child class may not know which implementation to use.

This is commonly called the diamond problem.

Java uses interfaces to support multiple inheritance of type and certain forms of behavior.

### 48. What is polymorphism?

Polymorphism means one thing can have multiple forms.

In Java, the same method name can behave differently depending on the parameters or the actual object.

There are two types:

- Compile-time polymorphism.
- Runtime polymorphism.

### 49. What is compile-time polymorphism?

Compile-time polymorphism is achieved through method overloading.

The compiler determines which method to call based on the method arguments.

### 50. What is runtime polymorphism?

Runtime polymorphism is achieved through method overriding.

The JVM determines which overridden instance method to execute based on the actual object.

### 51. What is method overloading?

Method overloading means having multiple methods with the same name but different parameter lists in the same class.

```
class Calculator {
    int add(int a, int b) {
        return a + b;
    }

    int add(int a, int b, int c) {
        return a + b + c;
    }
}
```

### 52. What is method overriding?

Method overriding happens when a child class provides its own implementation of an inherited instance method.

```
class Animal {
    void sound() {
        System.out.println("Animal sound");
    }
}

class Dog extends Animal {
    @Override
    void sound() {
        System.out.println("Barking");
    }
}
```

### 53. What are the rules of method overriding?

1. The method name must be the same.
2. The parameter list must be the same.
3. The return type must be the same or covariant.
4. Access visibility cannot be reduced.
5. Final methods cannot be overridden.
6. Private methods cannot be overridden.
7. Static methods are hidden, not overridden.
8. Checked exceptions cannot be broader than those allowed by the parent method.

### 54. Can static methods be overridden?

No. Static methods cannot be overridden because they belong to the class.

If a child class defines a static method with the same signature, it is called method hiding.

### 55. Can private methods be overridden?

No. Private methods are not inherited by child classes.

Therefore, they cannot be overridden.

### 56. Can we override a method with a different return type?

Yes, but only if the return type is the same or covariant.

Covariant return type means the child method can return a subclass of the parent's return type.

For example, if the parent returns `Animal`, the child can return `Dog`.

### 57. What is abstraction?

Abstraction means hiding implementation details and showing only essential functionality to the user.

For example, when we use an ATM, we perform operations without knowing the internal implementation.

### 58. How do you achieve abstraction in Java?

Abstraction is achieved using:

1. Abstract classes.
2. Interfaces.

### 59. What is an abstract class?

An abstract class is a class declared using the `abstract` keyword.

It cannot be instantiated directly.

It can contain:

- Abstract methods.
- Concrete methods.
- Constructors.
- Variables.
- Static methods.

### 60. What is an interface?

An interface is a reference type that defines a contract that implementing classes agree to follow.

It supports abstraction and multiple inheritance of type.

```
interface Animal {
    void sound();
}

class Dog implements Animal {
    public void sound() {
        System.out.println("Barking");
    }
}
```

### 61. Difference between abstract class and interface?

| Abstract class                         | Interface                                              |
| -------------------------------------- | ------------------------------------------------------ |
| Declared using `abstract class`        | Declared using `interface`                             |
| Can have constructors                  | Cannot have constructors                               |
| Can have instance variables            | Fields are implicitly public, static and final         |
| Supports abstract and concrete methods | Supports abstract, default, static and private methods |
| A class can extend only one class      | A class can implement multiple interfaces              |

### 62. Can an interface have constructors?

No. Interfaces cannot have constructors because we cannot directly create objects of an interface.

### 63. Can an interface have variables?

Yes. But interface variables are automatically:

- public
- static
- final

Example:

```
interface Demo {
    int VALUE = 100;
}
```

### 64. Can an abstract class have a constructor?

Yes. An abstract class can have a constructor.

It is called when a child class object is created, as part of the parent constructor execution.

### 65. What are default and static methods in interfaces?

Default method: A method with an implementation inside an interface, declared using `default`.

Static method: A method belonging to the interface itself, called using the interface name.

```
interface Demo {
    default void show() {
        System.out.println("Default method");
    }

    static void display() {
        System.out.println("Static method");
    }
}
```

### 66. What is the diamond problem?

The diamond problem occurs when a class inherits the same method implementation from two different parent types, creating ambiguity.

Java avoids this problem with classes by not supporting multiple class inheritance.

When interfaces have conflicting default methods, the implementing class must resolve the conflict by overriding the method.

### 67. What is association?

Association represents a relationship between two independent classes.

Example: A Teacher teaches Students.

Both Teacher and Student can exist independently.

### 68. What is aggregation?

Aggregation is a weak HAS-A relationship.

One object contains or refers to another object, but both can exist independently.

Example: A Department has Teachers. Even if the department is removed, teachers can still exist.

### 69. What is composition?

Composition is a strong HAS-A relationship.

The contained object is owned by the parent object and its lifecycle is generally tied to the parent.

Example: A House contains Rooms.

If the House is destroyed, its Rooms as parts of that House generally cease to exist.

### 70. Explain the difference between IS-A and HAS-A relationships.

IS-A: Represents inheritance.

Example: Dog IS-A Animal.

HAS-A: Represents composition or aggregation.

Example: Car HAS-A Engine.

# C. String Handling (71–80)

### 71. What is String in Java?

String is a class in Java used to store a sequence of characters.

Example:

```
String name = "Java";
```

String is immutable, which means its value cannot be changed after the object is created.

### 72. Why is String immutable?

String is immutable mainly for:

1. Security: Prevents unwanted modification of sensitive values.
2. Thread safety: Multiple threads can safely share String objects.
3. String pool: Allows safe sharing and reuse of String objects.
4. Hashing: Its hash code can be cached because its value does not change.

### 73. What is the String Constant Pool?

String Constant Pool is a special area within the heap where Java maintains reusable String objects.

Example:

```
String a = "Java";
String b = "Java";

System.out.println(a == b); // true
```

Both variables refer to the same pooled String object.

### 74. Difference between String and StringBuilder?

| String                                             | StringBuilder                             |
| -------------------------------------------------- | ----------------------------------------- |
| Immutable                                          | Mutable                                   |
| Cannot modify original object                      | Can modify the same object                |
| Repeated concatenation may create multiple objects | More efficient for repeated modifications |
| Thread-safe due to immutability                    | Not synchronized                          |

Example:

```
StringBuilder sb = new StringBuilder("Hello");
sb.append(" Java");

System.out.println(sb); // Hello Java
```

### 75. Difference between StringBuilder and StringBuffer?

Both are mutable classes used to modify strings.

| StringBuilder                             | StringBuffer                                                    |
| ----------------------------------------- | --------------------------------------------------------------- |
| Not synchronized                          | Synchronized                                                    |
| Generally faster                          | Generally slower                                                |
| Not thread-safe by itself                 | Thread-safe for individual synchronized operations              |
| Used mainly in single-threaded situations | Useful when synchronized mutable string operations are required |

### 76. What happens when we create a String using `new`?

When we create a String using `new`, Java explicitly creates a new String object on the heap.

Example:

```
String a = "Java";
String b = new String("Java");

System.out.println(a == b); // false
```

Here, `a` refers to the pooled object, while `b` refers to a separate object.

### 77. What is the intern() method?

The `intern()` method returns the canonical String from the String pool.

If an equivalent pooled String exists, it returns that reference. Otherwise, it arranges for the String to become the canonical pooled representation.

Example:

```
String a = new String("Java");
String b = a.intern();

System.out.println(b == "Java"); // true
```

### 78. Difference between equals() and == for Strings?

- `==` checks whether two references point to the same object.
- `equals()` checks whether their character contents are equal.

Example:

```
String a = new String("Hello");
String b = new String("Hello");

System.out.println(a == b);      // false
System.out.println(a.equals(b)); // true
```

### 79. How do you reverse a String?

We can use StringBuilder.

```
String str = "Java";

String reversed = new StringBuilder(str)
                    .reverse()
                    .toString();

System.out.println(reversed);
```

Output:

```
avaJ
```

### 80. How do you check whether a String is a palindrome?

A palindrome is a word that reads the same forward and backward.

Example: `madam`.

```
String str = "madam";

String reversed = new StringBuilder(str)
                    .reverse()
                    .toString();

if (str.equals(reversed)) {
    System.out.println("Palindrome");
} else {
    System.out.println("Not Palindrome");
}
```

# D. Collections Framework (81–110)

### 81. What is the Java Collections Framework?

The Java Collections Framework is a set of interfaces and classes used to store and manipulate groups of objects.

It provides ready-made data structures such as:

- ArrayList
- LinkedList
- HashSet
- TreeSet
- HashMap

### 82. What is the difference between Collection and Collections?

Collection: An interface that represents a group of objects.

Collections: A utility class that provides static methods to perform operations on collections.

Example:

```
Collections.sort(list);
Collections.reverse(list);
```

### 83. Explain the Collection Framework hierarchy.

The main hierarchy is:

```
Iterable
   |
Collection
   |
   |--- List
   |      |--- ArrayList
   |      |--- LinkedList
   |      |--- Vector
   |
   |--- Set
   |      |--- HashSet
   |      |--- LinkedHashSet
   |      |--- SortedSet
   |              |--- TreeSet
   |
   |--- Queue
          |--- PriorityQueue
          |--- Deque
                 |--- ArrayDeque
```

Map is a separate interface. It does not extend Collection.

Its main implementations include:

```
Map
 |
 |--- HashMap
 |--- LinkedHashMap
 |--- Hashtable
 |--- SortedMap
        |--- TreeMap
```

### 84. Difference between List, Set and Map?

| List                       | Set                               | Map                           |
| -------------------------- | --------------------------------- | ----------------------------- |
| Allows duplicates          | Does not allow duplicate elements | Does not allow duplicate keys |
| Maintains positional order | Depends on implementation         | Depends on implementation     |
| Index-based access         | No index-based access             | Uses key-value pairs          |
| Example: ArrayList         | Example: HashSet                  | Example: HashMap              |

### 85. Difference between ArrayList and LinkedList?

| ArrayList                                              | LinkedList                                                             |
| ------------------------------------------------------ | ---------------------------------------------------------------------- |
| Uses a dynamic array                                   | Uses a doubly linked list                                              |
| Fast random access                                     | Slow random access                                                     |
| Middle insertion/removal can require shifting elements | Insertion/removal is efficient when the node position is already known |
| Generally uses less memory                             | Requires extra memory for links                                        |

Interview answer: I prefer ArrayList when frequent searching and accessing elements are required. LinkedList can be useful for frequent insertions and removals through an iterator or at the ends.

### 86. Difference between ArrayList and Vector?

| ArrayList                              | Vector                                     |
| -------------------------------------- | ------------------------------------------ |
| Not synchronized                       | Synchronized                               |
| Generally faster                       | Generally slower                           |
| Grows by approximately 50% when needed | Traditionally doubles capacity when needed |
| Modern general-purpose choice          | Legacy collection                          |

### 87. Difference between HashSet and LinkedHashSet?

| HashSet                            | LinkedHashSet             |
| ---------------------------------- | ------------------------- |
| Does not guarantee iteration order | Maintains insertion order |
| Generally slightly less overhead   | Requires extra memory     |
| Allows unique elements             | Allows unique elements    |

### 88. Difference between HashSet and TreeSet?

| HashSet                           | TreeSet                                          |
| --------------------------------- | ------------------------------------------------ |
| Uses hashing                      | Uses a tree-based structure                      |
| No guaranteed sorted order        | Stores elements in sorted order                  |
| Average O(1) basic operations     | O(log n) basic operations                        |
| Generally allows one null element | Natural ordering generally does not support null |

### 89. Difference between HashMap and Hashtable?

| HashMap                                      | Hashtable                          |
| -------------------------------------------- | ---------------------------------- |
| Not synchronized                             | Synchronized                       |
| Allows one null key and multiple null values | Does not allow null keys or values |
| Generally faster                             | Generally slower                   |
| Modern general-purpose choice                | Legacy class                       |

### 90. Difference between HashMap and LinkedHashMap?

| HashMap                       | LinkedHashMap                        |
| ----------------------------- | ------------------------------------ |
| No guaranteed iteration order | Maintains insertion order by default |
| Less memory overhead          | More memory overhead                 |
| Fast lookup                   | Fast lookup with order maintenance   |

LinkedHashMap can also be configured to maintain access order.

### 91. Difference between HashMap and TreeMap?

| HashMap                    | TreeMap                                   |
| -------------------------- | ----------------------------------------- |
| Uses hashing               | Uses a Red-Black tree                     |
| No guaranteed sorted order | Keys are sorted                           |
| Average O(1) get and put   | O(log n) get and put                      |
| Allows one null key        | Natural ordering does not allow null keys |

### 92. How does HashMap work internally?

HashMap stores data in key-value pairs.

Internally, it uses an array of buckets.

When we insert a value:

1. HashMap calculates the key's hash code.
2. It calculates the bucket index.
3. It stores the key-value pair in that bucket.
4. If another key maps to the same bucket, collision handling is performed.
5. If the key already exists according to `equals()`, its value is replaced.

In Java 8 and later, a heavily populated bucket can be converted from a linked list into a balanced tree when the implementation's conditions are met.

### 93. How does HashSet work internally?

HashSet internally uses a HashMap.

When we add an element to HashSet, it stores that element as a key in the internal HashMap and uses a common dummy object as the value.

Because HashMap does not allow duplicate keys, HashSet does not allow duplicate elements.

### 94. Can HashMap contain duplicate keys?

No. HashMap does not allow duplicate keys.

If we insert the same key again, its existing value will be replaced.

Example:

```
HashMap<Integer, String> map = new HashMap<>();

map.put(1, "Java");
map.put(1, "Python");

System.out.println(map);
```

Output:

```
{1=Python}
```

### 95. Can HashMap contain null keys and values?

Yes.

HashMap allows:

- One null key.
- Multiple null values.

Example:

```
map.put(null, "Java");
map.put(1, null);
map.put(2, null);
```

### 96. What happens when two keys have the same hashCode?

When two keys have the same hash code, a collision occurs if they map to the same bucket.

HashMap handles the collision using a linked list or, under certain conditions, a balanced tree.

It uses `equals()` to distinguish between keys.

### 97. What is collision handling in HashMap?

Collision handling is the process of managing multiple keys that map to the same bucket.

Java HashMap uses:

1. Linked lists for ordinary collisions.
2. Balanced trees for sufficiently large buckets when the treeification conditions are satisfied.

### 98. What is load factor?

Load factor determines how full a HashMap can become before resizing is triggered.

The default load factor is `0.75`.

For example, if the capacity is 16:

```
Threshold = 16 × 0.75
          = 12
```

When the number of entries exceeds the threshold, HashMap resizes its internal table when required.

### 99. What is initial capacity?

Initial capacity is the initial number of buckets allocated for a HashMap.

The default initial capacity is 16.

Example:

```
HashMap<Integer, String> map = new HashMap<>(32);
```

Here, we specify an initial capacity of 32.

### 100. What is ConcurrentHashMap?

ConcurrentHashMap is a thread-safe implementation of the Map interface.

It allows multiple threads to access and modify the map safely without synchronizing the entire map for every operation.

It does not allow null keys or null values.

### 101. Difference between HashMap and ConcurrentHashMap?

| HashMap                                                            | ConcurrentHashMap                    |
| ------------------------------------------------------------------ | ------------------------------------ |
| Not thread-safe                                                    | Thread-safe                          |
| Allows null key and values                                         | Does not allow null keys or values   |
| No built-in concurrency protection                                 | Supports concurrent access           |
| Suitable for single-threaded use or externally synchronized access | Suitable for concurrent applications |

### 102. What is an Iterator?

Iterator is an interface used to traverse elements in a collection.

It provides methods such as:

- `hasNext()`
- `next()`
- `remove()`

Example:

```
Iterator<Integer> it = list.iterator();

while (it.hasNext()) {
    System.out.println(it.next());
}
```

### 103. Difference between Iterator and ListIterator?

| Iterator               | ListIterator                         |
| ---------------------- | ------------------------------------ |
| Works with collections | Works only with List implementations |
| Forward traversal      | Forward and backward traversal       |
| Cannot add elements    | Can add elements                     |
| Can remove elements    | Can remove and replace elements      |

### 104. What is fail-fast behaviour?

Fail-fast behaviour means an iterator may throw `ConcurrentModificationException` if a collection is structurally modified during iteration, except through the iterator's permitted operations.

Example:

```
List<Integer> list = new ArrayList<>();
list.add(10);
list.add(20);

for (Integer i : list) {
    list.add(30);
}
```

This can throw `ConcurrentModificationException`.

Fail-fast behaviour is best-effort, not a guaranteed concurrency mechanism.

### 105. What is fail-safe behaviour?

Fail-safe is an informal term commonly used for iterators that can tolerate concurrent modification.

For example, CopyOnWriteArrayList uses snapshot-based iterators.

The iterator works with a snapshot and does not reflect subsequent modifications.

### 106. What is Comparable?

Comparable is an interface used to define the natural ordering of objects.

It contains the `compareTo()` method.

Example:

```
class Student implements Comparable<Student> {
    int age;

    public int compareTo(Student s) {
        return this.age - s.age;
    }
}
```

### 107. What is Comparator?

Comparator is an interface used to define custom sorting logic.

It contains the `compare()` method.

Example:

```
Comparator<Integer> c = (a, b) -> b - a;
```

This sorts integers in descending order.

### 108. Difference between Comparable and Comparator?

| Comparable                            | Comparator                         |
| ------------------------------------- | ---------------------------------- |
| Uses compareTo()                      | Uses compare()                     |
| Defines natural ordering              | Defines custom ordering            |
| Implemented by the class being sorted | Can be implemented separately      |
| Usually one natural ordering          | Multiple custom orderings possible |

### 109. How do you sort a list of custom objects?

We can use Comparable or Comparator.

Example using Comparator:

```
class Student {
    int age;

    Student(int age) {
        this.age = age;
    }
}

List<Student> list = new ArrayList<>();

list.add(new Student(25));
list.add(new Student(20));
list.add(new Student(22));

list.sort((a, b) -> a.age - b.age);
```

This sorts students by age in ascending order.

### 110. When would you use ArrayList instead of LinkedList?

I would use ArrayList when:

- Frequent random access is required.
- Searching by index is common.
- Insertions and removals are mostly at the end.
- Memory efficiency is important.

In most general-purpose applications, ArrayList is a good default choice.

# E. Java 8 and Modern Java (111–135)

### 111. What are the important features introduced in Java 8?

Important Java 8 features include:

1. Lambda expressions.
2. Functional interfaces.
3. Stream API.
4. Default methods in interfaces.
5. Static methods in interfaces.
6. Method references.
7. Optional class.
8. New Date and Time API.
9. CompletableFuture.

### 112. What is a Lambda Expression?

A lambda expression is a short way of writing an implementation of a functional interface.

It reduces unnecessary code.

Example:

Traditional approach:

```
Runnable r = new Runnable() {
    public void run() {
        System.out.println("Hello");
    }
};
```

Using lambda:

```
Runnable r = () -> System.out.println("Hello");
```

### 113. What is a Functional Interface?

A functional interface is an interface that contains exactly one abstract method.

It can also contain default, static and private methods.

Example:

```
@FunctionalInterface
interface Calculator {
    int add(int a, int b);
}
```

### 114. What is the @FunctionalInterface annotation?

It is an annotation used to indicate that an interface is intended to be a functional interface.

The compiler checks that it has exactly one abstract method.

If we declare multiple unrelated abstract methods, compilation fails.

### 115. What are Predicate, Function, Consumer and Supplier?

These are commonly used functional interfaces in Java.

| Interface | Purpose                           | Method   |
| --------- | --------------------------------- | -------- |
| Predicate | Checks a condition                | test()   |
| Function  | Accepts input and returns output  | apply()  |
| Consumer  | Accepts input but returns nothing | accept() |
| Supplier  | Supplies a value without input    | get()    |

Example:

```
Predicate<Integer> p = n -> n > 10;

Function<Integer, Integer> f = n -> n * 2;

Consumer<String> c = s -> System.out.println(s);

Supplier<Integer> s = () -> 100;
```

### 116. What is the Stream API?

Stream API is a Java feature used to process collections of data in a functional style.

It supports operations like:

- filter()
- map()
- sorted()
- collect()
- reduce()

Example:

```
List<Integer> numbers = List.of(1, 2, 3, 4, 5);

numbers.stream()
       .filter(n -> n % 2 == 0)
       .forEach(System.out::println);
```

Output:

```
2
4
```

### 117. What is the difference between Collection and Stream?

| Collection                            | Stream                              |
| ------------------------------------- | ----------------------------------- |
| Stores data                           | Processes data                      |
| Can be used multiple times            | A stream can be consumed only once  |
| Data structure                        | Processing pipeline                 |
| Supports adding and removing elements | Does not directly modify the source |

### 118. What is the difference between map() and flatMap()?

map(): Transforms each element into another element.

flatMap(): Transforms each element into a stream or other supported result and flattens the results into one stream.

Example:

```
List<String> names = List.of("Abi", "Ravi");

List<Integer> lengths = names.stream()
    .map(String::length)
    .toList();
```

Using flatMap:

```
List<List<Integer>> numbers =
    List.of(List.of(1, 2), List.of(3, 4));

List<Integer> result = numbers.stream()
    .flatMap(List::stream)
    .toList();
```

Output:

```
[1, 2, 3, 4]
```

### 119. Difference between filter() and map()?

filter(): Selects elements based on a condition.

map(): Transforms each element into another value.

Example:

```
numbers.stream()
       .filter(n -> n > 10);
```

This selects numbers greater than 10.

```
numbers.stream()
       .map(n -> n * 2);
```

This doubles each number.

### 120. What are intermediate and terminal operations?

Intermediate operations: Return another stream and are generally lazy.

Examples:

- filter()
- map()
- sorted()
- distinct()

Terminal operations: Produce a result or side effect and trigger stream processing.

Examples:

- collect()
- forEach()
- count()
- reduce()

### 121. What is lazy evaluation in Streams?

Lazy evaluation means intermediate stream operations are not executed immediately.

They execute only when a terminal operation is called.

Example:

```
numbers.stream()
       .filter(n -> n > 10)
       .map(n -> n * 2)
       .count();
```

The processing happens when `count()` is executed.

### 122. What is the difference between findFirst() and findAny()?

- `findFirst()` returns the first element according to the stream's encounter order, if one exists.
- `findAny()` returns any element and is useful when working with parallel streams.

Both return an Optional.

### 123. What is reduce()?

`reduce()` combines multiple elements into a single result.

Example:

```
int sum = List.of(1, 2, 3, 4)
              .stream()
              .reduce(0, Integer::sum);
```

Output:

```
10
```

### 124. What is Optional?

Optional is a container object that may or may not contain a non-null value.

It was introduced in Java 8 to represent potentially missing values more clearly.

Example:

```
Optional<String> name = Optional.of("Java");
```

### 125. How do you avoid NullPointerException using Optional?

We can use methods like:

- ofNullable()
- isPresent()
- orElse()
- orElseGet()
- orElseThrow()
- map()

Example:

```
String name = null;

String result = Optional.ofNullable(name)
                        .orElse("Default");

System.out.println(result);
```

Output:

```
Default
```

### 126. What is method reference?

Method reference is a shorter way of referring to an existing method using `::`.

Example:

```
List<String> names = List.of("Abi", "Ravi");

names.forEach(System.out::println);
```

It is equivalent to:

```
names.forEach(name -> System.out.println(name));
```

### 127. What is a constructor reference?

A constructor reference is used to refer to a constructor using `::new`.

Example:

```
Supplier<ArrayList<String>> supplier =
        ArrayList::new;

ArrayList<String> list = supplier.get();
```

It creates a new ArrayList.

### 128. What are default methods in interfaces?

Default methods are methods with implementations inside interfaces.

They were introduced in Java 8 to allow interfaces to add new methods without forcing every existing implementing class to implement them.

### 129. What is the Date and Time API?

Java 8 introduced the `java.time` package for date and time handling.

Important classes include:

- LocalDate
- LocalTime
- LocalDateTime
- ZonedDateTime
- Instant
- Period
- Duration

Example:

```
LocalDate date = LocalDate.now();

System.out.println(date);
```

### 130. What is the difference between parallelStream() and stream()?

stream(): Processes elements sequentially by default.

parallelStream(): Processes elements using parallel execution, generally through the common ForkJoinPool.

Parallel streams can improve performance for suitable large workloads, but they can also introduce overhead and ordering considerations.

### 131. What are records in modern Java?

Records were introduced as a standard feature in Java 16.

They provide a concise way to create classes mainly used to store data.

Example:

```
record Student(String name, int age) {
}
```

Java automatically provides:

- Constructor.
- Accessor methods.
- equals().
- hashCode().
- toString().

A record is implicitly final, and its component fields are final. However, if a component refers to a mutable object, that object itself may still be modified.

### 132. What are sealed classes?

Sealed classes were introduced as a standard feature in Java 17.

They restrict which classes can extend or implement them.

Example:

```
sealed class Animal permits Dog, Cat {
}

final class Dog extends Animal {
}

final class Cat extends Animal {
}
```

It gives better control over inheritance.

### 133. What is the var keyword?

The `var` keyword was introduced in Java 10 for local variable type inference.

The compiler automatically determines the variable type from its initializer.

Example:

```
var name = "Java";
var age = 25;
```

Here, the compiler identifies String and int respectively.

`var` cannot be used for fields, method parameters or return types.

### 134. What are switch expressions?

Switch expressions were introduced as a standard feature in Java 14.

They allow switch to return a value.

Example:

```
int day = 1;

String result = switch(day) {
    case 1 -> "Monday";
    case 2 -> "Tuesday";
    default -> "Invalid";
};
```

### 135. What are text blocks?

Text blocks were introduced as a standard feature in Java 15.

They allow us to write multiline strings using triple double quotes.

Example:

```
String message = """
        Hello,
        Welcome to Java.

```

They make multiline text easier to read.

# F. Exception Handling (136–150)

### 136. What is an exception?

An exception is an unwanted event that occurs during program execution and interrupts the normal flow of the program.

Example:

```
int a = 10 / 0;
```

This causes ArithmeticException.

### 137. Explain the Java exception hierarchy.

The Java exception hierarchy starts with Throwable.

```
Object
  |
Throwable
  |
  |--- Error
  |
  |--- Exception
          |
          |--- Checked Exceptions
          |
          |--- RuntimeException
                  |
                  |--- Unchecked Exceptions
```

Examples:

- Error: OutOfMemoryError.
- Checked: IOException.
- Unchecked: NullPointerException.

### 138. What is the difference between Error and Exception?

| Error                                                             | Exception                                    |
| ----------------------------------------------------------------- | -------------------------------------------- |
| Serious problem generally associated with JVM or system resources | Problem an application may be able to handle |
| Usually not intended to be caught                                 | Can often be handled                         |
| Example: OutOfMemoryError                                         | Example: IOException                         |

### 139. Difference between checked and unchecked exceptions?

Checked exceptions: Checked by the compiler. We must handle them using try-catch or declare them using throws.

Examples: IOException, SQLException.

Unchecked exceptions: Not checked by the compiler.

Examples: NullPointerException, ArithmeticException, ArrayIndexOutOfBoundsException.

### 140. What is try-catch?

Try-catch is used to handle exceptions and prevent abnormal program termination when an exception can be handled.

- `try` contains risky code.
- `catch` handles the exception.

Example:

```
try {
    int result = 10 / 0;
} catch (ArithmeticException e) {
    System.out.println("Cannot divide by zero");
}
```

### 141. Can we have multiple catch blocks?

Yes. We can have multiple catch blocks to handle different exceptions separately.

Example:

```
try {
    int a = 10 / 0;
} catch (ArithmeticException e) {
    System.out.println("Arithmetic error");
} catch (Exception e) {
    System.out.println("General error");
}
```

Important: More specific exceptions must come before their parent exception.

### 142. What is the finally block?

The finally block is used to execute cleanup code after try-catch processing.

It generally executes whether an exception occurs or not.

Example:

```
try {
    System.out.println("Try block");
} catch (Exception e) {
    System.out.println("Catch block");
} finally {
    System.out.println("Finally block");
}
```

### 143. Will finally execute if a return statement is present?

Yes. Normally, the finally block executes even if there is a return statement in the try or catch block.

Example:

```
static int test() {
    try {
        return 10;
    } finally {
        System.out.println("Finally");
    }
}
```

The output is:

```
Finally
```

The method returns 10.

However, finally is not guaranteed to execute in situations such as JVM termination using `System.exit()` or abrupt process termination.

### 144. What is the difference between throw and throws?

throw: Used to explicitly throw an exception.

throws: Used in a method declaration to indicate exceptions that the method may propagate to its caller.

Example:

```
void checkAge(int age) {
    if (age < 18) {
        throw new IllegalArgumentException("Not eligible");
    }
}
```

Using throws:

```
void readFile() throws IOException {
    // File reading code
}
```

### 145. What is a custom exception?

A custom exception is an exception created by the programmer to represent application-specific errors.

Example: InvalidAgeException, InsufficientBalanceException.

### 146. How do you create a custom checked exception?

We extend the Exception class.

```
class InvalidAgeException extends Exception {
    InvalidAgeException(String message) {
        super(message);
    }
}
```

Usage:

```
void checkAge(int age) throws InvalidAgeException {
    if (age < 18) {
        throw new InvalidAgeException("Age is invalid");
    }
}
```

### 147. What is try-with-resources?

Try-with-resources is used to automatically close resources after use.

It was introduced in Java 7.

It works with objects that implement AutoCloseable.

Example:

```
try (FileReader reader = new FileReader("test.txt")) {
    int data = reader.read();
} catch (IOException e) {
    System.out.println(e.getMessage());
}
```

The reader is automatically closed.

### 148. What is the difference between final, finally and finalize?

- `final`: Keyword used to restrict modification, overriding or inheritance.
- `finally`: Block used in exception handling for cleanup.
- `finalize()`: Deprecated method historically associated with garbage collection.

### 149. What happens when an exception occurs inside a catch block?

If an exception occurs inside a catch block, the remaining statements in that catch block are skipped.

The new exception propagates to the caller unless another suitable handler handles it.

The finally block, if present, normally executes before the exception propagates.

### 150. What happens when an exception occurs inside a finally block?

If an exception occurs inside finally, it can propagate to the caller.

If another exception was already propagating from the try or catch block, the finally exception can replace and hide the original exception.

This is one reason why we should avoid throwing exceptions from finally blocks unnecessarily.

# G. Multithreading and Concurrency (151–175)

### 151. What is a process?

A process is a program that is currently running.

It has its own memory space and system resources.

Example: Running a browser or a Java application.

### 152. What is a thread?

A thread is the smallest unit of execution within a process.

A Java application can have multiple threads performing different tasks.

Example: One thread handles user requests while another processes background tasks.

### 153. Difference between process and thread?

| Process                              | Thread                                    |
| ------------------------------------ | ----------------------------------------- |
| Independent running program          | Unit of execution within a process        |
| Has its own memory space             | Shares process memory                     |
| Creation is generally more expensive | Creation is generally less expensive      |
| Communication can be more complex    | Threads communicate through shared memory |

### 154. How do you create a thread in Java?

There are two traditional ways:

1. Extending the Thread class.
2. Implementing the Runnable interface.

Example using Runnable:

```
class MyTask implements Runnable {
    public void run() {
        System.out.println("Thread running");
    }
}

class Main {
    public static void main(String[] args) {
        Thread t = new Thread(new MyTask());
        t.start();
    }
}
```

### 155. Difference between Thread and Runnable?

| Thread                                     | Runnable                             |
| ------------------------------------------ | ------------------------------------ |
| Class                                      | Functional interface                 |
| We extend Thread                           | We implement Runnable                |
| Cannot extend another class simultaneously | Can still extend another class       |
| Combines task and thread representation    | Separates task from thread execution |

Generally, Runnable is preferred because it provides better separation of responsibilities.

### 156. What is the Callable interface?

Callable is a functional interface used to define a task that returns a result and can throw checked exceptions.

It contains the `call()` method.

Example:

```
Callable<Integer> task = () -> 10 + 20;
```

### 157. Difference between Runnable and Callable?

| Runnable                                                  | Callable                           |
| --------------------------------------------------------- | ---------------------------------- |
| Has run() method                                          | Has call() method                  |
| Does not return a result                                  | Returns a result                   |
| Cannot declare checked exceptions in its method signature | Can declare checked exceptions     |
| Used for tasks without a return value                     | Used for tasks that return results |

### 158. What are the different thread states?

Java defines six thread states:

1. NEW
2. RUNNABLE
3. BLOCKED
4. WAITING
5. TIMED_WAITING
6. TERMINATED

### 159. What is the thread life cycle?

The thread life cycle represents the different states of a thread.

```
NEW
 |
start()
 |
RUNNABLE
 |
Executing / Running
 |
 |--- BLOCKED
 |--- WAITING
 |--- TIMED_WAITING
 |
RUNNABLE
 |
TERMINATED
```

Note: In Java's official Thread.State enum, RUNNABLE includes threads that are executing and threads that are ready to execute.

### 160. What is synchronization?

Synchronization is a mechanism used to control access to shared resources by multiple threads.

It prevents multiple threads from executing a critical section simultaneously when they use the same synchronization lock.

It helps prevent race conditions.

### 161. What is a synchronized method?

A synchronized method allows only one thread at a time to execute that method using the same object's monitor lock.

Example:

```
synchronized void display() {
    System.out.println("Hello");
}
```

For a static synchronized method, the lock is associated with the Class object.

### 162. What is a synchronized block?

A synchronized block is used to synchronize only a specific section of code rather than the entire method.

Example:

```
void display() {
    synchronized(this) {
        System.out.println("Hello");
    }
}
```

It can improve concurrency by reducing the amount of code protected by the lock.

### 163. What is deadlock?

Deadlock is a situation where two or more threads wait indefinitely for locks held by each other.

Example:

- Thread 1 holds Lock A and waits for Lock B.
- Thread 2 holds Lock B and waits for Lock A.

Neither thread can continue.

### 164. How can you prevent deadlock?

We can reduce the possibility of deadlock by:

1. Acquiring locks in a consistent order.
2. Avoiding unnecessary nested locks.
3. Keeping synchronized blocks small.
4. Using timed lock acquisition with `tryLock()` where appropriate.
5. Avoiding circular lock dependencies.

### 165. What is the volatile keyword?

The volatile keyword ensures that reads and writes of a variable have the required visibility and ordering guarantees across threads.

When one thread updates a volatile variable, other threads can observe the updated value.

Example:

```
volatile boolean running = true;
```

Important: Volatile does not make compound operations such as `count++` atomic.

### 166. Difference between sleep() and wait()?

| sleep()                                | wait()                                            |
| -------------------------------------- | ------------------------------------------------- |
| Method of Thread                       | Method of Object                                  |
| Pauses the current thread              | Makes a thread wait for notification or timeout   |
| Does not release held monitor locks    | Releases the monitor lock on the object           |
| Can be called without owning a monitor | Must be called while owning that object's monitor |

### 167. Difference between notify() and notifyAll()?

notify(): Wakes up one waiting thread on the object's monitor.

notifyAll(): Wakes up all threads waiting on that object's monitor.

The awakened threads must still compete to reacquire the monitor.

### 168. What is the ExecutorService framework?

ExecutorService is a Java concurrency framework used to manage and execute asynchronous tasks.

Instead of manually creating threads, we submit tasks to an executor.

Example:

```
ExecutorService executor =
        Executors.newFixedThreadPool(2);

executor.submit(() -> {
    System.out.println("Task running");
});

executor.shutdown();
```

### 169. What is a thread pool?

A thread pool is a group of reusable worker threads.

Instead of creating a new thread for every task, we reuse existing threads.

Benefits:

- Reduces thread creation overhead.
- Controls the number of active threads.
- Improves resource management.

### 170. What is CompletableFuture?

CompletableFuture is a Java class used to perform asynchronous and non-blocking operations.

It supports chaining multiple asynchronous tasks.

Example:

```
CompletableFuture.supplyAsync(() -> 10)
    .thenApply(n -> n * 2)
    .thenAccept(System.out::println);
```

Output:

```
20
```

### 171. What is the difference between synchronized and Lock?

| synchronized                                                           | Lock                                     |
| ---------------------------------------------------------------------- | ---------------------------------------- |
| Built-in Java keyword                                                  | Interface in java.util.concurrent.locks  |
| Automatically releases the monitor when leaving the synchronized block | Requires explicit unlock()               |
| Does not directly support timed lock acquisition                       | Supports tryLock() and timed acquisition |
| Simpler to use                                                         | Provides more locking flexibility        |

### 172. What is a race condition?

A race condition occurs when multiple threads access and modify shared data, and the final result depends on the timing or order of execution.

Example:

Two threads simultaneously execute `count++`.

Both may read the same old value and overwrite each other's updates.

We can prevent this using synchronization, locks or atomic classes.

### 173. What is ThreadLocal?

ThreadLocal provides a separate copy of a variable for each thread.

Each thread accesses its own value without sharing it with other threads.

Example:

```
ThreadLocal<Integer> local =
        ThreadLocal.withInitial(() -> 0);

local.set(100);

System.out.println(local.get());
```

It is commonly used for thread-specific context.

Important: In thread pools, call `remove()` when the thread-specific value is no longer needed to avoid retaining unwanted data.

### 174. What is atomicity in concurrent programming?

Atomicity means an operation happens as one indivisible unit.

Other threads cannot observe it in a partially completed state.

Example:

`AtomicInteger` provides atomic operations such as `incrementAndGet()`.

```
AtomicInteger count = new AtomicInteger(0);

count.incrementAndGet();
```

### 175. What is the difference between parallelism and concurrency?

Concurrency: Multiple tasks make progress during overlapping periods of time. They may take turns on the same CPU.

Parallelism: Multiple tasks execute at the same time, usually using multiple CPU cores.

Example:

- Concurrency: One CPU switches between multiple tasks.
- Parallelism: Two CPU cores execute two tasks simultaneously.

# H. Advanced Java, JDBC and Memory (176–195)

### 176. What is JDBC?

JDBC stands for Java Database Connectivity.

It is a Java API used to connect Java applications with databases.

Using JDBC, we can:

- Establish database connections.
- Execute SQL queries.
- Insert, update and delete records.
- Retrieve data.
- Manage database transactions.

### 177. Explain JDBC architecture.

JDBC architecture explains how a Java application communicates with a database.

Main components:

1. Java Application.
2. JDBC API.
3. JDBC DriverManager or DataSource.
4. JDBC Driver.
5. Database.

Flow:

```
Java Application
       |
       v
    JDBC API
       |
       v
DriverManager / DataSource
       |
       v
   JDBC Driver
       |
       v
    Database
```

### 178. What are the steps involved in connecting Java to a database?

The main steps are:

1. Import JDBC packages.
2. Establish a database connection.
3. Create a Statement or PreparedStatement.
4. Execute the SQL query.
5. Process the ResultSet if the query returns data.
6. Close the resources.

Example:

```
Connection con = DriverManager.getConnection(
    "jdbc:mysql://localhost:3306/studentdb",
    "root",
    "password"
);

PreparedStatement ps =
    con.prepareStatement("SELECT * FROM student");

ResultSet rs = ps.executeQuery();

while (rs.next()) {
    System.out.println(rs.getString("name"));
}

rs.close();
ps.close();
con.close();
```

In real applications, we generally use try-with-resources to close resources safely.

### 179. What is a JDBC Driver?

A JDBC Driver is software that allows a Java application to communicate with a specific database.

Examples:

- MySQL JDBC Driver.
- PostgreSQL JDBC Driver.
- Oracle JDBC Driver.

It translates JDBC calls into database-specific communication.

### 180. What is the difference between Statement and PreparedStatement?

| Statement                                                      | PreparedStatement                                               |
| -------------------------------------------------------------- | --------------------------------------------------------------- |
| Used for ordinary SQL statements                               | Used for parameterized SQL statements                           |
| SQL is generally constructed as a string                       | SQL can contain placeholders (?)                                |
| More vulnerable to SQL injection when concatenating user input | Helps prevent SQL injection when parameters are bound correctly |
| Generally suitable for simple static SQL                       | Suitable for repeated parameterized queries                     |

Example using Statement:

```
Statement st = con.createStatement();

ResultSet rs = st.executeQuery(
    "SELECT * FROM student"
);
```

Example using PreparedStatement:

```
PreparedStatement ps = con.prepareStatement(
    "SELECT * FROM student WHERE id = ?"
);

ps.setInt(1, 101);

ResultSet rs = ps.executeQuery();
```

### 181. Difference between PreparedStatement and CallableStatement?

| PreparedStatement                  | CallableStatement                     |
| ---------------------------------- | ------------------------------------- |
| Executes parameterized SQL queries | Executes stored procedures            |
| Uses `?` placeholders              | Supports IN, OUT and INOUT parameters |
| Used for SQL operations            | Used for calling database procedures  |

Example:

```
CallableStatement cs =
    con.prepareCall("{call getStudent(?)}");

cs.setInt(1, 101);

ResultSet rs = cs.executeQuery();
```

### 182. What is SQL injection?

SQL injection is a security attack where an attacker inserts malicious SQL statements into application inputs.

It can allow unauthorized database access or modification.

Example of unsafe code:

```
String query =
    "SELECT * FROM users WHERE username = '"
    + username + "'";
```

An attacker could manipulate the input to change the query's meaning.

### 183. How does PreparedStatement prevent SQL injection?

PreparedStatement uses parameterized queries.

It separates SQL instructions from user-provided values.

Example:

```
String query =
    "SELECT * FROM users WHERE username = ?";

PreparedStatement ps = con.prepareStatement(query);

ps.setString(1, username);
```

The input is treated as a parameter value rather than executable SQL syntax.

### 184. What is ResultSet?

ResultSet is a JDBC interface used to store and access the data returned by a SELECT query.

We use the `next()` method to move through the returned rows.

Example:

```
while (rs.next()) {
    System.out.println(rs.getInt("id"));
    System.out.println(rs.getString("name"));
}
```

### 185. What is Connection Pooling?

Connection pooling is a technique where database connections are created and maintained in a reusable pool.

Instead of creating a new database connection for every request, applications reuse existing connections.

Benefits:

1. Improves performance.
2. Reduces connection creation overhead.
3. Saves database resources.
4. Handles multiple requests efficiently.

Example: HikariCP is a popular JDBC connection pool used with Spring Boot.

### 186. What is transaction management in JDBC?

Transaction management is used to ensure that a group of database operations is executed reliably.

A transaction follows ACID properties:

- Atomicity.
- Consistency.
- Isolation.
- Durability.

Example: In a bank transfer, money should be deducted from one account and added to another account as one transaction.

### 187. What are commit() and rollback()?

commit(): Permanently saves the changes made during a transaction.

rollback(): Cancels uncommitted changes made during a transaction.

Example:

```
con.setAutoCommit(false);

try {
    // Execute SQL operations

    con.commit();

} catch (Exception e) {
    con.rollback();
}
```

### 188. What is batch processing in JDBC?

Batch processing means executing multiple SQL statements together instead of executing them individually.

It improves performance when inserting or updating many records.

Example:

```
PreparedStatement ps =
    con.prepareStatement(
        "INSERT INTO student(id, name) VALUES(?, ?)"
    );

ps.setInt(1, 1);
ps.setString(2, "Abi");
ps.addBatch();

ps.setInt(1, 2);
ps.setString(2, "Ravi");
ps.addBatch();

ps.executeBatch();
```

### 189. What is serialization?

Serialization is the process of converting an object's state into a byte stream.

It is useful for storing objects or transferring them between systems.

A class generally implements the Serializable interface.

Example:

```
class Student implements Serializable {
    int id;
    String name;
}
```

### 190. What is deserialization?

Deserialization is the reverse process of serialization.

It converts a byte stream back into an object.

Example:

```
ObjectInputStream in =
    new ObjectInputStream(
        new FileInputStream("student.ser")
    );

Student s = (Student) in.readObject();
```

Deserialization of untrusted data can be dangerous, so input should be validated and protected.

### 191. What is the transient keyword?

The transient keyword is used with instance fields to indicate that they should not be included in Java's default serialization.

Example:

```
class Student implements Serializable {
    int id;
    transient String password;
}
```

Here, `password` is skipped during default serialization.

### 192. What is reflection in Java?

Reflection is a feature that allows Java programs to inspect and interact with classes, methods, constructors and fields at runtime.

It is available through the `java.lang.reflect` package.

Example:

```
Class<?> c = Student.class;

System.out.println(c.getName());
```

Reflection is commonly used in frameworks such as Spring, Hibernate and JUnit.

### 193. What is the difference between shallow copy and deep copy?

Shallow copy:

Creates a new object but copies references to nested objects.

So, both objects may share the same nested objects.

Deep copy:

Creates a new object and also copies its nested mutable objects.

The original and copied objects are independent.

Example:

Imagine an Employee object contains an Address object.

- Shallow copy: Both Employee objects may refer to the same Address.
- Deep copy: Each Employee object has a separate Address object.

### 194. What is a memory leak in Java?

A memory leak happens when an application unnecessarily retains references to objects that are no longer needed.

Because those objects are still reachable, garbage collection cannot reclaim them.

Common reasons:

1. Static collections holding unused objects.
2. Improper use of listeners.
3. Unclosed resources.
4. Incorrect ThreadLocal usage.
5. Unbounded caches.

Example:

```
static List<Object> list = new ArrayList<>();

void addData() {
    for (int i = 0; i < 100000; i++) {
        list.add(new Object());
    }
}
```

If the list continuously grows and the objects are no longer needed, memory usage increases.

### 195. How do you identify memory leaks?

We can identify memory leaks using:

1. Heap Dump: Takes a snapshot of objects in heap memory.
2. VisualVM: Helps monitor memory usage and inspect heap dumps.
3. JProfiler: Helps analyze memory and performance.
4. Java Flight Recorder (JFR): Helps monitor application runtime behaviour.
5. GC Logs: Help understand garbage collection activity.

We can identify objects that are consuming more memory and check why they are still reachable.
